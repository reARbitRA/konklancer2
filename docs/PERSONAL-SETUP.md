# راه‌اندازی شخصی Konklancer — «برای خودم اسکن کن»

این سند برای کسی است که می‌خواهد Konklancer را **روی کامپیوتر خودش، برای خودش** اجرا کند:
اسکنر فهرست عمومی پروژه‌ها را بخواند، فید واقعی در UI بیاید، و از آنجا تحلیل/پروپوزال/کد بگیرد.

> اجرای این ابزار عمداً «فقط‌خواندنی» است: بدون ورود به حساب، بدون ارسال پیشنهاد، بدون دور زدن کپچا.
> با همین محدودیت هم می‌شود روزانه چند برابر سریع‌تر پروژه‌ی مناسب را پیدا و پیشنهاد را آماده کرد.

---

## ۰) در یک نگاه

| مرحله | دستور/کار | زمان لازم |
|---|---|---|
| ۱. نصب | `npm install --legacy-peer-deps` + `pip install httpx beautifulsoup4 pytest` | ~۳ دقیقه |
| ۲. تنظیم `.env` | `cp .env.example .env` و پر کردن مقدارها | ~۲ دقیقه |
| ۳. (اختیاری) AI مستقیم | واردکردن کلید شخصی و انتخاب مدل در Settings بعد از نصب | ~۲ دقیقه |
| ۴. فعال‌کردن یک منبع | صفحه‌ی ذخیره‌شده در مرورگر (فوری) / تلگرام / کالیبراسیون یک پلتفرم | ۲ تا ۲۰ دقیقه |
| ۵. اسکن | دکمه‌ی «اسکن زنده» در UI یا `npm run scan` | چند ثانیه تا چند دقیقه |

---

## ۰.۵) قدم صفر: ۲ دقیقه‌ای ببینید چه چیزی می‌گیرید (بدون هیچ اسکنی)

یک فید نمونه با فرمت واقعی در مخزن هست (`scanner/tests/fixtures/feed_sample.jsonl`). با آن می‌توانید
کل محصول (فید، امتیاز، لینک پروژه، تحلیل، پروپوزال) را بدون تماس با هیچ سایتی ببینید:

```bash
npm install --legacy-peer-deps
KONKLANCER_PROJECTS_FILE=scanner/tests/fixtures/feed_sample.jsonl npm start
# http://localhost:3000 → تب «شکار پروژه» → نوار بالای صفحه باید بگوید «فید واقعی از اسکنر»
```

رکوردهای این فایل ساختگی‌اند (دامنه‌ی `example.invalid`) و صرفاً برای دیدن رفتار UI هستند؛ وقتی
اسکنر خودتان را راه انداختید، `KONKLANCER_PROJECTS_FILE` را به `.env` نبرید یا به فایل فید خودتان
اشاره دهید.

## ۱) پیش‌نیازها

- **Node.js 22+** و **Python 3.10+**
- بسته‌های پایتون اسکنر:
  ```bash
  pip install httpx beautifulsoup4 pytest        # یا: python3 -m venv .venv && .venv/bin/pip install ...
  ```
- (اختیاری، برای AI) یک کلید API شخصی از provider مورد نظرت که بعد از نصب در Settings وارد می‌کنی؛ لازم نیست gateway یا Supabase را راه‌اندازی کنی.

> اگر پایتون را در venv نصب کردید، مسیرش را به Konklancer بگویید:
> `KONKLANCER_PYTHON=".venv/bin/python"`

## ۲) نصب و اجرا

```bash
npm install --legacy-peer-deps      # یک تضاد peer بین esbuild و vite وجود دارد
cp .env.example .env                # مقادیر را پر کنید
npm start                           # http://localhost:3000
```

در اولین اجرا در لاگ سرور می‌بینید:

```
[scanner] فید: .../scanner/out/projects.jsonl · 0 پروژه در فایل · 0 منبع فعال
[scanner] هیچ منبعی فعال نیست؛ فید خالی می‌ماند. راهنمای راه‌اندازی شخصی: docs/PERSONAL-SETUP.md
```

این پیام‌ها را جدی بگیرید: تا وقتی «۰ منبع فعال» است، UI خالی می‌ماند (و هیچ داده‌ی ساختگی نشان
داده نمی‌شود؛ حالت دمو فقط با `KONKLANCER_DEMO=1` روشن می‌شود).

### متغیرهای محیطی مربوط به اسکن

| نام | پیش‌فرض | توضیح |
|---|---|---|
| `KONKLANCER_SCAN_PLATFORMS` | خالی | شناسه‌ی پلتفرم‌های کالیبره‌شده، با کاما: `parscoders,ponisha` |
| `KONKLANCER_SCAN_TELEGRAM` | `0` | اگر `1` باشد، کانال‌هایی که `scan_enabled=true` دارند اسکن می‌شوند |
| `KONKLANCER_SCAN_INCLUDE` / `..._EXCLUDE` | خالی | کلیدواژه‌ها با کاما (فارسی هم می‌شود). **خالی = بدون فیلتر: همه‌ی دسته‌ها اسکن می‌شوند** |
| `KONKLANCER_SCAN_CATEGORIES` | خالی | محدودکردن به دسته‌های مشخص (`translation,graphic`). خالی = همه‌ی دسته‌ها |
| `KONKLANCER_SCAN_AUTO` | `1` | کشف خودکار ساختار صفحه در زمان اسکن (برای اسکن فقط با انتخابگر ذخیره‌شده: `0`) |
| `KONKLANCER_SCAN_PAGES` | `1` | تعداد صفحه‌ی فهرست هر پلتفرم |
| `KONKLANCER_SCAN_DELAY` | `8` | فاصله‌ی ثانیه بین درخواست‌ها (قاعده‌ی ایمنی اسکنر) |
| `KONKLANCER_SCAN_MIN_SCORE` | `0` | فقط پروژه‌های با امتیاز بزرگ‌تر از این مقدار وارد فید شوند (مثلاً `60`) |
| `KONKLANCER_SCAN_INTERVAL_MIN` | `0` | اسکن خودکار هر N دقیقه؛ `0` = خاموش |
| `KONKLANCER_PROJECTS_FILE` | `scanner/out/projects.jsonl` | محل فید JSONL |
| `KONKLANCER_PYTHON` | `python3` | مفسر پایتون برای اجرای اسکنر |
| `KONKLANCER_SCAN_TIMEOUT_MS` | `180000` | مهلت کل یک اجرای اسکن |

## ۳) AI مستقیم از provider (حالت موقت)

تا وقتی gateway آماده شود، درخواست‌های تحلیل، دسته‌بندی، پیشنهاد و تولید فایل مستقیماً از مرورگر/APK
به provider انتخاب‌شده فرستاده می‌شوند؛ مسیر AI از Konkred یا Supabase نمی‌گذرد.

1. در هدر روی سوییچر کلید/مدل یا در Settings روی گاوصندوق API بزن.
2. یک پروفایل اضافه کن و provider را انتخاب کن: OpenRouter، Google Gemini، Groq، OpenAI، Ollama/local،
   یا endpoint سازگار مثل DeepSeek.
3. کلید شخصی خودت را در همان دستگاه وارد کن؛ اتصال را آزمایش کن و فهرست مدل‌ها را اسکن کن.
4. پروفایل و مدل دلخواه را فعال کن. می‌توان چند پروفایل داشت؛ failover اختیاری است.

**کلید را بعد از نصب، در خود برنامه روی دستگاه وارد کن؛ داخل APK یا کد قرارش نده.** APK حتی برای
استفاده‌ی شخصی قابل بازکردن است و کلید bundleشده قابل استخراج خواهد بود. کلیدهای پروفایل در storage
همان دستگاه نگه‌داری می‌شوند و درخواست‌ها مستقیم به provider می‌روند. هرگز آن‌ها را در چت نفرست.

در حالت direct، دسترسی به provider به CORS، شبکه، منطقه و محدودیت سهمیه‌ی همان provider وابسته است.
اگر درخواست مسدود شود، برنامه خطای واقعی را نشان می‌دهد؛ رله‌ی Supabase/Vercel یا پاسخ ساختگی جایگزین
نمی‌شود. بدون پروفایل فعال، قابلیت‌های فید و اسکن کار می‌کنند و عملیات AI خطای نیاز به کلید می‌دهد.

متغیرهای gateway در `.env` برای این حالت لازم نیستند؛ SPEC-006 تا درخواست بعدی مالک متوقف است.

## ۴) فعال‌کردن منابع اسکن

سه مسیر دارید. اگر می‌خواهید همین امروز داده‌ی واقعی ببینید، **مسیر الف** را انتخاب کنید.

---

### الف) مسیر بی‌دردسر: صفحه را در مرورگر ذخیره کنید، ساختار خودش کشف می‌شود

این مسیر هیچ درخواست خودکاری به سایت نمی‌فرستد (خودتان صفحه را باز و ذخیره می‌کنید)، پس به robots
یا ضدربات کاری ندارد و همیشه کار می‌کند — و **به نوشتن انتخابگر دستی هم نیازی ندارد**:

1. در مرورگر، صفحه‌ی فهرست پروژه‌ها را باز کنید (مثلاً `parscoders.com/project/only-available/1`).
2. `Ctrl+S` → ذخیره به‌صورت «Webpage, HTML only» (مثلاً `/tmp/parscoders-1.html`).
3. در ترمینال (کشف خودکار ساختار + نوشتن در فید):

```bash
python -m scanner.konklancer_scan autoscan --platform parscoders \
  --html /tmp/parscoders-1.html --save --out scanner/out/projects.jsonl
```

خروجی چیزی شبیه این است (امتیاز و تعداد آیتم واقعی، از خودِ فایل):

```
[parscoders] کشف خودکار: div.project-card (24 آیتم، امتیاز 88.1)
[parscoders] صفحه 1: 24 پروژه
دسته‌ها: ترجمه و ویراستاری: 5 · گرافیک، لوگو و بروشور: 4 · وب و اپلیکیشن: 6 · ...
24 مورد خوانده شد؛ 24 پس از فیلتر؛ 24 مورد جدید در scanner/out/projects.jsonl
```

4. اول با `--save` نزنید و فقط ببینید چه چیزی کشف می‌شود؛ اگر منطقی بود با `--save` انتخابگرها را
   در `platforms.json` ماندگار کنید (پس‌ازآن `scan`/`autoscan` بدون `--html` هم استفاده می‌کند).
5. در UI دکمه‌ی «اسکن زنده» را بزنید (یا صفحه را تازه کنید) — پروژه‌ها به فید اضافه شده‌اند.

> اگر سایت ساختار عجیبی داشت و کشف خودکار چیزی نداد، با `autodetect --html FILE` ببینید چه نامزدهایی
> پیدا می‌شوند و اگر لازم شد انتخابگر دستی بدهید (مثل `--selectors-json` در `parse-file`).
> مراحل دقیق در [scanner/README.md](../scanner/README.md).
>
> همین کار برای کانال‌های تلگرام هم هست: صفحه‌ی `https://t.me/s/<username>` را ذخیره کنید و
> ```bash
> python -m scanner.konklancer_scan parse-telegram-file --channel workarc \
>   --html /tmp/tg-workarc.html --include پایتون --out scanner/out/projects.jsonl
> ```

### ب) تلگرام با اسکن خودکار (اگر `robots.txt` اجازه داد)

کانال‌های عمومی از پیش‌نمایش `t.me/s/<username>` خوانده می‌شوند و **انتخابگر CSS لازم نیست**:

```bash
python -m scanner.konklancer_scan list                      # کدام کانال‌ها موجودند؟
python -m scanner.konklancer_scan enable --telegram workarc  # فعال‌کردن یک کانال
```

و در `.env`: `KONKLANCER_SCAN_TELEGRAM="1"`.

⚠️ **پیش از فعال‌کردن، خودتان `https://t.me/robots.txt` را در مرورگر باز کنید.** اسکنر به `robots.txt`
هر میزبان احترام می‌گذارد و اگر مسیر `/s/` منع شده باشد، (به‌درستی) متوقف می‌شود و در لاگ می‌نویسد
`robots.txt این مسیر را ممنوع کرده است`. اگر robots.txt خوانده نشود (قطعی شبکه / خطای ۵xx)، آن میزبان
محافظه‌کارانه برای همان اجرا کنار گذاشته می‌شود — در این حالت مسیر (الف) را استفاده کنید.

کانال‌ها و وضعیتشان در `scanner/telegram_sources.json` است. هر پیام یک «پروژه‌ی بالقوه» است و پیش از
هر اقدامی باید خودتان بررسی کنید.

---

### ج) پلتفرم‌ها با اسکن زنده‌ی خودکار (کشف ساختار در همان لحظه)

پارس‌کدرز، پونیشا و کارلنسر از قبل «نامزد نشانی و انتخابگر» دارند (برگرفته از کد عمومی مخزن
`reARBitRA/all-them-bots`؛ **تأییدنشده** چون ساختار واقعی باید از صفحه‌ی زنده دیده شود). مسیر
پیشنهادی: اول کشف خودکار، بعد ماندگارکردن انتخابگر تأییدشده.

```bash
# ۱) نامزدها را روی صفحه‌ی زنده امتحان کن و بهترین را ذخیره کن
python -m scanner.konklancer_scan probe --platform parscoders --save

# ۲) یا یک‌مرحله‌ای: خواندن صفحه + کشف خودکار + نوشتن در فید
python -m scanner.konklancer_scan autoscan --platform parscoders,ponisha --pages 2 --save

# ۳) یا با اسکنر سرور (همان `scan` که سرور اجرا می‌کند، با --auto پیش‌فرض)
python -m scanner.konklancer_scan scan --platform parscoders,ponisha --pages 2 --auto
```

سپس در `.env`: `KONKLANCER_SCAN_PLATFORMS="parscoders,ponisha"`.

اگر خواستید انتخابگر ثابتی داشته باشید:

```bash
python -m scanner.konklancer_scan snapshot --platform parscoders      # ذخیره‌ی صفحه برای بررسی دستی
python -m scanner.konklancer_scan autodetect --platform parscoders --html SAVED.html --save --min-count 5
python -m scanner.konklancer_scan parse-file --platform parscoders --html SAVED.html  # بررسی خروجی
python -m scanner.konklancer_scan enable --platform parscoders
```

`enable --platform` فقط پلتفرمی را قبول می‌کند که یا انتخابگر ثبت‌شده دارد یا نامزد نشانی
(تا اسکن بی‌نتیجه نداشته باشید).

> پیش از فعال‌کردن هر سایت، `robots.txt` آن را خودتان بخوانید. در بررسی ۱۰ اکتبر ۲۰۲۶ پونیشا
> `/robots.txt` را با ۴۰۴ پاسخ می‌داد (یعنی محدودیتی اعلام نشده) و کارلنسر `/api*` و `/search?q=*` را
> منع کرده بود. اسکنر فقط `GET` می‌زند، ۸ ثانیه بین درخواست‌ها فاصله می‌گذارد و اگر صفحه به دامنه‌ی
> دیگری ریدایرکت شود، متوقف می‌شود.
>
> **اگر سایت با JS رندر می‌شود یا ربات‌ها را می‌بندد** (کارلنسر شایع‌ترین گزینه است)، `autoscan` روی
> صفحه‌ی زنده ممکن است صفر آیتم برگرداند. در آن حالت مسیر (الف) با `--html` را بروید؛ داده همان
> صفحه‌ی واقعی است که خودتان در مرورگر دیده‌اید. Playwright هنوز پیاده نشده است.

## ۴.۵) اگر کامپیوتر ندارید: اسکن ابری روی گیت‌هاب (بدون نصب چیزی)

اگر روی ماشین خودتان به سایت‌های فریلنسری دسترسی ندارید (فیلتر، شبکه‌ی محدود، یا سندباکس/مرورگر)،
همان اسکنر واقعی روی **رانرهای گیت‌هاب** اجرا می‌شود: آنجا اینترنت آزاد است. ورک‌فلو:
`.github/workflows/scanner-feed.yml`.

**یک‌بار تنظیم (در `.env` سرور):**

```env
KONKLANCER_CLOUD_FEED_REPO="reARbitRA/konklancer"
KONKLANCER_CLOUD_FEED_REF="main"          # برنچی که ورک‌فلو روی آن است
KONKLANCER_CLOUD_TOKEN=""                  # خالی = استفاده از `gh auth token`
```

**بعد فقط از UI استفاده کنید:**

- دکمه‌ی **«اسکن ابری»** → ورک‌فلو را روی گیت‌هاب اجرا می‌کند، تا پایان کار صبر می‌کند و فید را می‌آورد.
- دکمه‌ی **«همگام‌سازی»** → آخرین فید آماده را می‌کشد (بدون اجرای اسکن تازه).

**معادل خط فرمان / API:**

```bash
curl -s -X POST localhost:3000/api/bridge/cloud-scan   | jq .   # درخواست اسکن ابری
curl -s -X POST localhost:3000/api/bridge/sync-feed    | jq .   # فقط همگام‌سازی فید
curl -s      localhost:3000/api/bridge/cloud           | jq .   # وضعیت آخرین اجرا + عیب‌یابی
```

آنچه ورک‌فلو در هر اجرا انجام می‌دهد و روی برنچ کامیت می‌کند:

| خروجی | چیست |
|---|---|
| `scanner/cloud-feed.jsonl` | فید واقعی (JSONL) که UI می‌خواند — بدون هیچ داده‌ی ساختگی |
| `scanner/cloud-status.json` | وضعیت و خلاصه‌ی عیب‌یابی (کد پاسخ هر میزبان، تعداد هر دسته) |
| `scanner/tests/fixtures/live/*.html.gz` | نمونه‌ی HTML واقعی سایت‌ها برای کالیبراسیون و تست آفلاین |

**پاک‌سازی فید و ردیف‌های زباله**

اگر فیدی از قبل مانده و ردیف‌های بی‌ربط (منو، «خانه»، صفحه‌ی دسته‌بندی، کانال غیرفعال) در آن هست:

```bash
python -m scanner.konklancer_scan prune --file scanner/cloud-feed.jsonl          # فقط گزارش
python -m scanner.konklancer_scan prune --file scanner/cloud-feed.jsonl --apply  # پاک‌سازی
```

همین پاک‌سازی در هر اجرای ورک‌فلوی ابری هم خودکار انجام می‌شود (دسته‌ی «نشانی‌های غیرپروژه»).

**اگر گواهی TLS سرور شما سفارشی است** (پروکسی سازمانی/سندباکس) و `fetch` نود خطای
«unable to verify the first certificate» می‌دهد: سرور را با `NODE_EXTRA_CA_CERTS=/path/to/ca.crt`
اجرا کنید. اگر این هم ممکن نبود، خودِ سرور به‌صورت خودکار همان درخواست را با CLI رسمی `gh api`
انجام می‌دهد؛ روشِ استفاده‌شده در `GET /api/bridge/cloud` زیر کلید `transport` گزارش می‌شود.

محدودیت‌های همین مسیر (صادقانه):

- رانر گیت‌هاب IP خارج از ایران دارد؛ سایت‌هایی که به IP خارجی سخت می‌گیرند (پارس‌کدرز در اجرای ما
  تایم‌اوت داد، پونیشا روی یکی از مسیرها ۵۰۳ داد) ممکن است کامل جواب ندهند. مسیر جایگزین همان
  «ذخیره‌ی صفحه در مرورگر» (بخش الف) است.
- اجرای زمان‌بندی‌شده (`cron`) فقط وقتی فعال می‌شود که این ورک‌فلو روی برنچ پیش‌فرض باشد؛ روی
  برنچ‌های دیگر با هر تغییر در `scanner/scan-request.json` اجرا می‌شود.
- مصرف دقایق Actions: هر اجرا حدود ۲ تا ۳ دقیقه.

## ۵) اجرای اسکن

سه راه، همه یک کار می‌کنند:

1. **دکمه‌ی «اسکن زنده»** در نوار بالای تب «شکار پروژه» یا در تب «اتوپایلوت».
2. **HTTP:**
   ```bash
   curl -s -X POST http://localhost:3000/api/bridge/trigger-scan | jq .
   ```
3. **خط فرمان (بدون اجرای UI):**
   ```bash
   npm run scan                      # همان اسکنر، با تنظیمات .env
   # یا مستقیم (بدون فیلتر ⇒ همه‌ی دسته‌ها: ترجمه، گرافیک، ویدیو، صدا، کد، ...):
   python -m scanner.konklancer_scan scan --platform parscoders,ponisha --pages 2 --auto
   python -m scanner.konklancer_scan scan --telegram
   ```

**اسکن خودکار دوره‌ای** (اختیاری): در `.env` مقدار `KONKLANCER_SCAN_INTERVAL_MIN=30` بگذارید؛ سرور
هر ۳۰ دقیقه یک بار (با قفل، بدون هم‌پوشانی) اسکن می‌کند و پروژه‌های تازه را با Socket.io به UI پوش
می‌دهد.

**زمان‌بندی با cron** (اگر UI روشن نیست ولی می‌خواهید فید به‌روز باشد):

```cron
*/30 * * * * cd /path/to/konklancer && /usr/bin/python3 -m scanner.konklancer_scan autoscan --platform parscoders,ponisha --pages 2 >> scanner/out/cron.log 2>&1
```

## ۶) تنظیم سلیقه: چه پروژه‌ای برای شما «خوب» است؟

هر پروژه در فید یک **امتیاز ۰ تا ۱۰۰** می‌گیرد که پیش از هر تماس AI و کاملاً قاعده‌محور حساب می‌شود:

| عامل | وزن | توضیح |
|---|---|---|
| بودجه | تا ۴۰ | از `budget_text` (ارقام فارسی و لاتین، «میلیون/هزار/میلیارد»، «ریال» هم پشتیبانی می‌شود) |
| رقابت | تا ۲۵ | تعداد پیشنهادها؛ بدون پیشنهاد = ۲۵، بالای ۱۵ پیشنهاد = ۳ |
| تازگی | تا ۱۵ | زیر ۶ ساعت = ۱۵ |
| هم‌پوشانی کلیدواژه | تا ۲۰ | هر کلیدواژه‌ی `KONKLANCER_SCAN_INCLUDE` که در عنوان/خلاصه باشد |
| تناسب دسته با AI | تا ۵ | دسته‌ی پروژه (ترجمه/گرافیک/... که AI می‌تواند تولید کند) کمی جلو می‌افتد |

> **هیچ کلیدواژه‌ای پروژه را حذف نمی‌کند:** اگر `KONKLANCER_SCAN_INCLUDE` را پر کنید و پروژه‌ای با
> کلیدواژه‌ها نخواند، امتیاز خنثی (+۸) می‌گیرد و در فید می‌ماند. حذف فقط با `..._EXCLUDE` یا
> `..._CATEGORIES` (محدودکردن صریح) انجام می‌شود.

- با `KONKLANCER_SCAN_MIN_SCORE=60` فقط پروژه‌های ارزشمند وارد فید می‌شوند (و همان‌ها بعداً به
  `analyze-job` می‌روند؛ این همان پیش‌فیلتر `SPEC-004 R5` است).
- امتیاز و دلایلش روی کارت هر پروژه دیده می‌شود (نگه‌داشتن نشانگر روی «امتیاز فید»).
- ترتیب فید از بالاترین امتیاز است.

## ۷) گردش کار روزانه‌ی پیشنهادی (۱۰–۱۵ دقیقه)

1. `اسکن زنده` → فید تازه.
2. روی پروژه‌های بالای امتیاز ۶۰: **تحلیل هوش مصنوعی** (امتیاز اتومات‌پذیری، قیمت پیشنهادی، ریسک).
3. **نگارش پروپوزال** → ویرایش انسانی (لحن خودتان) → کپی.
4. **صفحه‌ی پروژه** را باز کنید و پیشنهاد را خودتان ثبت کنید (ابزار عمداً این کار را خودکار نمی‌کند).
5. در تب **پایپ‌لاین** وضعیت را به «ارسال پیشنهاد» ببرید تا یادآور و آمار داشته باشید.
6. اگر پروژه را گرفتید: تب **کدنویسی** → تولید سورس → **GitHub** (پیش‌فرض: مخزن خصوصی) → پیام تحویل
   را از دیالوگ کپی و در چت کارفرما بفرستید.

## ۸) چیزهایی که هنوز نیستند (صادقانه)

- **ثبت نتیجه و نرخ برد (SPEC-005)**: هنوز SQLite و `/api/bids` وجود ندارد؛ وضعیت‌ها در
  `localStorage` مرورگر ذخیره می‌شوند (پاک‌کردن داده‌ی مرورگر = از دست رفتن وضعیت‌ها).
- **دکمه‌ی «اجرای تست» در تب کدنویسی** یک لاگ نمایشی تولید می‌کند و کد را واقعاً اجرا نمی‌کند.
- **احراز هویت روی `/api/*`** هنوز اضافه نشده؛ اگر سرور را روی شبکه/اینترنت باز می‌کنید، این کار
  را نکنید (یا خودتان یک reverse proxy با auth بگذارید).
- **Playwright پیاده نشده است**؛ سایت‌های JS-محور (احتمالاً کارلنسر) با `autoscan` خالی می‌مانند —
  مسیر جایگزین: ذخیره‌ی صفحه در مرورگر و `autoscan --html`.
- **دسته‌بندی، فیلتر نیست:** دسته‌ی هر پروژه فقط برای نمایش/فیلتر UI است؛ اسکنر هیچ دسته‌ای را
  پیش‌فرض کنار نمی‌گذارد.
- تحلیل و پروپوزال با providerهای رایگان انجام می‌شود؛ ممکن است وقتی ظرفیت پر است پیام
  `AI_RATE_LIMITED` ببینید.

## ۹) عیب‌یابی

| نشانه | علت / راه‌حل |
|---|---|
| فید خالی و پیام «هیچ منبعی فعال نیست» | `KONKLANCER_SCAN_PLATFORMS`/`KONKLANCER_SCAN_TELEGRAM` تنظیم نشده یا منابع فعال نشده‌اند (بخش ۴). |
| `اجرای مفسر پایتون ناموفق بود` | پایتون یا بسته‌ها نصب نیستند؛ `KONKLANCER_PYTHON` را به مفسر درست بدهید. |
| `هیچ پلتفرم/کانالی فعال نیست` | برای تلگرام: `enable --telegram <username>`؛ برای پلتفرم: اول انتخابگرها. |
| `AI_NOT_CONFIGURED` | در Settings همین دستگاه پروفایل کلید فعال ندارید؛ یک کلید شخصی اضافه و فعال کنید (بخش ۳). |
| `AI_UNAVAILABLE` | درخواست مستقیم provider با خطای شبکه/CORS، اعتبار یا مدل روبه‌رو شده؛ «آزمایش اتصال» را اجرا و provider/model را بررسی کنید. |
| `robots.txt این مسیر را ممنوع کرده است` | سایت با ابزارهای خودکار موافق نیست؛ آن سایت/مسیر را اسکن نکنید و مسیر «ذخیره‌ی صفحه در مرورگر» (بخش ۴-الف) را امتحان کنید. |
| `robots.txt ... خوانده نشد (خطای شبکه یا بی‌دسترسی)` | یعنی دسترسی به `robots.txt` ممکن نشد؛ اسکنر محافظه‌کارانه متوقف می‌شود. اتصال/فیلترشکن را بررسی کنید. |
| پورت اشغال (`EADDRINUSE`) | سرور یا اجرای قبلی پورت پیش‌فرض ۳۰۰۰ را گرفته است: `PORT=4000 npm start`. |
