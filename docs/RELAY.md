# مسیر موقت AI مستقیم از provider

تا وقتی gateway آماده شود، همه‌ی عملیات AI برنامه از مرورگر/APK مستقیم به provider انتخاب‌شده می‌روند. در مسیر AI از Konkred، Supabase Edge، یا Vercel LLM relay استفاده نمی‌شود. این مسیر تحت SPEC-008 است؛ SPEC-006 هنوز APPROVED است اما فعلاً متوقف مانده.

## راه‌اندازی روی دستگاه

1. پس از نصب برنامه، در Settings یا سوییچر بالای صفحه یک پروفایل اضافه کن.
2. Provider را انتخاب کن: OpenRouter، Google Gemini، Groq، OpenAI، Ollama/local یا endpoint سازگار مثل DeepSeek.
3. کلید شخصی خودت را در همان دستگاه وارد کن، اتصال را آزمایش و فهرست مدل‌ها را اسکن کن.
4. مدل و پروفایل فعال را انتخاب کن. چند پروفایل پشتیبانی می‌شود؛ چرخش کلیدها قابل‌کنترل است.

## نگه‌داری کلیدها

کلید را در چت نفرست و آن را داخل کد، `.env` عمومی، سایت یا APK قرار نده. APK حتی اگر فقط خودت استفاده‌اش کنی قابل بازکردن است و کلید bundleشده قابل استخراج خواهد بود. کلید را بعد از نصب در Settings روی دستگاه وارد کن؛ برنامه آن را در storage همان دستگاه نگه می‌دارد. درخواست مستقیم شامل کلید انتخاب‌شده است و به provider فرستاده می‌شود.

کلیدهای provider نباید به `server.ts`, Supabase, gateway, یا build environment فرستاده شوند. Prompts تابع سیاست‌های نگه‌داری و استفاده‌ی provider انتخاب‌شده‌اند.

## شبکه و خطاها

تماس مستقیم به CORS، دسترسی شبکه/منطقه‌ای و سهمیه‌ی همان provider وابسته است. در صورت منع CORS یا خطای 401/403/429، برنامه خطای اصلی را نشان می‌دهد و به gateway، Supabase یا پاسخ ساختگی fallback نمی‌کند. Ollama فقط زمانی کار می‌کند که endpoint محلی روی دستگاهی که برنامه را اجرا می‌کند در دسترس باشد.

## دامنه‌ی Supabase

`scraper` و همگام‌سازی ابری قدیمی می‌توانند از helperهای جداگانه‌ی `src/services/cloudRelay.ts` استفاده کنند؛ این‌ها مسیر AI نیستند. برای SPEC-008 هیچ Edge Function یا تنظیم Supabase deploy/تغییر نمی‌شود.
