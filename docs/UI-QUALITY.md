# کیفیت UI/UX — چه چیزی شکسته بود و چطور تضمین شد

این سند سه باگ واقعی را ثبت می‌کند که با تست jsdom قابل کشف نبودند و فقط با اندازه‌گیری
هندسه در **Chromium واقعی** پیدا شدند. برای هرکدام: نشانه، ریشه، اصلاح، و تست نگهبان.

آخرین به‌روزرسانی: ۲۰۲۶-۱۰-۲۶

---

## ۱) هدر تبلت از قاب بیرون می‌زد → تبلت زوم‌اوت و اسکرول افقی

**نشانه:** روی تبلت کل صفحه ~۵۲px (در ۸۰۰px) و ~۹۲px (در ۱۲۸۰px) از پنجره پهن‌تر بود؛
کاربر باید افقی اسکرول می‌کرد و متن‌ها ریز/بریده دیده می‌شدند.

**ریشه:** ردیف هدر `shrink-0` روی خوشه‌ی اکشن‌ها داشت، ولی برند + چیپ حساب + سوئیچر
مدل + جستجو + اسکن + تنظیمات مجموعاً از عرض ۸۰۰px بیشتر می‌شد. هیچ‌کدام هم اجازه‌ی
کوچک‌شدن نداشتند، پس محتوا از قاب بیرون می‌زد و `document.scrollWidth` بزرگ‌تر از
ویوپورت می‌شد.

**اصلاح:**
- بریک‌پوینت‌ها بازچینش شد: ناوبری دسکتاپ از `xl`، برند (نشان + نام) از `lg`، شعارها از `2xl`.
- `LiveModelSwitcher` یک حالت `compact` گرفت: زیر ۱۲۸۰px فقط آیکون + نقطه‌ی وضعیت
  (نام مدل داخل همان پنل بازشو با تمام امکانات هست — چیزی حذف نشد).
- دکمه‌های اسکن/جستجو در موبایل مربع ۴۲px شدند و متن‌شان از `lg` نمایش داده می‌شود.
- `overflow-x: clip` روی `html, body` به‌عنوان تور ایمنی.

**نگهبان:** `npm run test:visual` — در ۷ ویوپورت (۳۶۰ تا ۱۶۰۰) و ۷ مسیر،
`scrollWidth ≤ viewport` و «هیچ عنصری بیرون از قاب» را چک می‌کند (پیش از اصلاح ۹۲px سرریز).

## ۲) پاپ‌اورها بیرون از صفحه باز می‌شدند و ریل کنترل روی تبلت مرده بود

**نشانه‌ها:**
- پنل سوئیچر مدل در ۸۰۰px با `right: 843 / left: 413` باز می‌شد؛ منوی حساب هم در
  ۳۶۰px تا `466px` می‌رفت. یعنی بخشی از محتوا بیرون از ویوپورت.
- دکمه‌ی همبرگری هدر («کنترل ریل») زیر ۱۰۲۴px هیچ کاری نمی‌کرد، چون خود ریل
  `hidden lg:flex` بود.

**اصلاح:**
- سوئیچر مدل: زیر `lg` به شکل "bottom sheet" (`inset-x-2 bottom-2`) و از `lg` به بعد
  به‌صورت dropdown چسبیده به دکمه.
- منوی حساب: زیر `sm` تمام‌عرض با `inset-x-2`، از `sm` به بعد `right-0` (RTL-aware).
- ریل کنترل: زیر `lg` به **کشوی کنار صفحه** تبدیل شد (با backdrop، بسته‌شدن با تپ/دکمه،
  `max-width: 340px`)، و از `lg` همان ریل ثابت قبلی.
- وضعیت اولیه‌ی ریل با `useState(() => matchMedia(...))` تعیین می‌شود؛ قبلاً با `useEffect`
  بعد از رندر ست می‌شد و یک لحظه کل صفحه را می‌پوشاند.

**نگهبان:** همان `test:visual` — باز شدن هر چهار overlay در ۳۶۰/۷۶۸/۸۰۰/۱۰۲۴ و
باز/بسته شدن کشو با backdrop.

## ۳) کل اپ هر ثانیه unmount/remount می‌شد (باگ اصلی «لگ» تبلت)

**نشانه:** تیک‌زدن هر کنترل محلی بی‌اثر بود (کشو باز نمی‌شد)، فیلترها/کارت باز/متن
فرم ریست می‌شد، و لیست ۷۷۰ کارتی مدام از نو ساخته می‌شد. اندازه‌گیری نشان داد
`InnerApp` هر ~۱ ثانیه یک‌بار mount/unmount می‌شود.

**ریشه:** `const InnerApp = () => {...}` **داخل** بدنه‌ی `App` تعریف شده بود. هر رندر
`App` یک تابع جدید می‌سازد، و از دید React **نوع کامپوننت جدید** است → کل زیرشاخه
unmount و از صفر mount می‌شد. هر تغییری در `App` (تیک زمان، سوکت، اسکن…) همه‌ی
state محلی پایین‌دست را نابود می‌کرد.

**اصلاح:** `InnerApp` به سطح ماژول منتقل شد و state/هندلرهای `App` از طریق یک
شیء `AppScope` (با تایپ دقیق برای اعضای پرکاربرد) به آن پاس داده می‌شود. حالا نوع
کامپوننت ثابت است و رندر مجدد، state را حفظ می‌کند.

**نگهبان:** `test:visual` پاس ۴: کشو باید بعد از ۲.۵ ثانیه بیکاری باز بماند و متن
تایپ‌شده نباید پاک شود. (پیش از اصلاح هر دو شکست می‌خوردند.)

## ۴) بهبودهای ارگونومی لمسی و چیدمان

- روی `pointer: coarse` (تبلت/گوشی) حداقل ارتفاع دکمه‌های ریز ۳۰–۳۴px شد تا تپ به
  کنترل مجاور نخورد؛ طراحی بصری فشرده دست‌نخورده مانده.
- نوار وضعیت پایین روی دستگاه لمسی ۳۶px و کلید میان‌بر «CTRL+K SEARCH» (که روی تبلت
  بی‌معنی است) پنهان می‌شود؛ خودِ دکمه‌ی جستجو در هدر همیشه در دسترس است.
- فید پروژه‌ها: یک ستون در گوشی، **دو ستون از `md`** (تبلت/لپ‌تاپ)، سه ستون از `2xl`.
- نشان برند دیگر بریده نمی‌شود (`whitespace-nowrap`؛ زیر `lg` فقط نشان آیکونی).

## چطور اجرا و تأیید کنیم

```bash
npm run build                    # بیلد تولیدی
PORT=24678 npm run dev           # سرور + اپ

# تست DOM (jsdom، بدون مرورگر واقعی) — ۱۰۱ چک
node scripts/dom-smoke.mjs

# تست چیدمان/تعامل در Chromium واقعی — ۱۰۶ چک
CHROMIUM_PATH=/path/to/chrome npm run test:visual
# نمونه روی یک محیط بدون GUI:
#   CHROMIUM_PATH=/tmp/chromium LD_LIBRARY_PATH=/tmp/libstub npm run test:visual

BASE_URL=http://127.0.0.1:24678   # اگر پورت دیگری داری
STRICT_TARGETS=false             # برای معاف‌کردن آستانه‌ی اندازه‌ی تپ‌ها
```

`test:visual` به `puppeteer-core` و یک باینری Chrome/Chromium نیاز دارد:
`npm i --no-save puppeteer-core` (مرورگر از سیستم/`CHROMIUM_PATH` خوانده می‌شود).

> **محدودیت این محیط:** سندباکس `libnss3/libnspr4` ندارد و اجازه‌ی `apt` هم نمی‌دهد.
> برای اجرای Chromium اینجا، کتابخانه‌های خالی (stub) با نمادهای نسخه‌دار ساخته شد
> (`/tmp/libstub`) چون فقط `http://127.0.0.1` بارگذاری می‌شد و مسیر TLS هرگز فراخوانی
> نشد. این راه‌حل فقط برای تست محلی است و در CI واقعی لازم نیست.
